# GPU variant of requirements.txt -- for B2 / B3 only.
#
# B0 and B1 do not need this; 5 parameters run fine on a CPU, which is why
# requirements.txt pins the CPU wheel. B2 and B3 are ~1.9M-parameter U-Nets
# over 84,911 training galaxies, and on CPU that is hours per seed.
#
# Install into a SEPARATE venv, so the working CPU environment that produced
# the official B0/B1 numbers is left exactly as it is:
#
#   python -m venv .venv-gpu
#   .venv-gpu\Scripts\activate       # Windows;  macOS/Linux: source .venv-gpu/bin/activate
#   pip install -r requirements-gpu.txt
#
# Then CHECK, because a CPU wheel installs silently and reports no GPU:
#
#   python -c "import torch; print(torch.__version__, torch.cuda.is_available())"
#
# Expect "2.14.1+cu130 True". A version ending "+cpu", or False, means pip
# resolved the wrong wheel -- see "If the pin is stale" below.

--index-url https://download.pytorch.org/whl/cu130
--extra-index-url https://pypi.org/simple

# The "+cu130" local version is load-bearing and must stay exact.
#
# PyPI also publishes torch 2.14.1, and on Windows that one is CPU-only. With a
# loose requirement like "torch>=2.0", pip compares the two indexes and takes
# the highest version it can find, which is how an earlier revision of this
# file -- pointing at cu128, whose newest Windows/cp311 wheel is 2.11.0 --
# silently installed 2.14.1+cpu from PyPI instead. The resulting environment
# weighed the same as the CPU one and reported cuda.is_available() == False on
# a perfectly good RTX 3050. Pinning the local version makes that substitution
# impossible: no PyPI release carries a "+cu130" tag.
#
# cu130 is chosen over cu126/cu128 because it is the only index carrying 2.14.1,
# which matches the CPU environment's torch version exactly -- so the GPU and
# CPU runs differ by build type alone, not by a point release as well.
torch==2.14.1+cu130

numpy>=1.24
h5py>=3.8
pyyaml>=6.0
scikit-image>=0.21      # PSNR / SSIM
scipy>=1.10             # solved reference optimum (also a scikit-image dependency)
matplotlib>=3.7

# -- If the pin is stale -------------------------------------------------------
#
# A newer torch, a different Python, or an older GPU may need another index.
# Do not loosen the pin; find the right one and pin that instead:
#
#   pip index versions torch --index-url https://download.pytorch.org/whl/cu130
#
# Then pin the exact version that command reports, keeping the "+cuXXX" suffix.
# The wheel's CUDA version does not have to match the driver's -- drivers are
# backward compatible -- but CUDA 13 wheels dropped support for GPUs older than
# Turing (sm_75), so pre-2018 cards need a cu12x index and an older torch.
#
# ~2.0 GB download, unpacking to roughly 4-6 GB once the bundled CUDA runtime,
# cuDNN and cuBLAS libraries land. An environment near 1 GB is a CPU one.
